# New API vs OfoxAI 功能对比调研报告

> 调研时间：2026-04-23
> 调研方式：源码分析 + Playwright 浏览器访问验证
> New API 地址：http://localhost:3000
> OfoxAI 地址：https://app.ofox.ai / https://ofox.ai

---

## 一、项目定位

| 维度 | New API | OfoxAI |
|------|---------|--------|
| 类型 | 开源 AI API Gateway | 商业 AI API SaaS 服务 |
| 技术栈 | Go + React | 闭源（Next.js） |
| 部署方式 | 自托管 | 云服务 |
| 版本 | - | v1.0.58 |
| 运营方 | QuantumNous | NICE TALK PTE. LTD. |

---

## 二、Chat 聊天功能

| 维度 | New API | OfoxAI |
|------|---------|--------|
| 内置 Playground | 有，支持文本对话、图片输入(Vision)、流式输出、参数调节(temperature/top_p/max_tokens等)、自定义请求体模式 | 无，只提供 Python/cURL/Node.js 代码示例 |
| 文生图测试 UI | 无专门 UI，但可通过自定义请求体调用 `images/generations` | 无，需自行编码调用 |
| 文生视频测试 UI | 无专门 UI | 无，需自行编码调用 |
| TTS 测试 UI | 无专门 UI，但后端支持 `audio/speech` | 无，需自行编码调用 |
| 第三方工具兼容 | 通用 OpenAI API 兼容 | 明确兼容 CherryStudio、Cursor、Claude Code、Chatbox、Cline、Codex、Zed、Windsurf、Aider 等 |

**结论**：New API 在**内置测试体验**上更好；OfoxAI 更偏向"纯 API 服务"定位，依赖用户自行集成。

## 三、API Key 管理

| 维度 | New API | OfoxAI |
|------|---------|--------|
| 创建 Key | 支持 | 支持 |
| 查看完整 Key | 支持（需安全验证） | 支持 |
| 编辑 Key（名称/过期/模型限制） | 支持 | 支持 |
| 删除/批量删除 | 支持 | 支持 |
| 复制 Key | 支持 | 支持 |
| Key 归属 | 个人用户 | **团队**（Team 级别管理） |

**结论**：OfoxAI 引入了**团队级 Key 管理**，适合多人协作场景；New API 偏向个人用户管理。

## 十、总体评估

| 评估维度 | New API | OfoxAI | 胜出方 |
|---------|---------|--------|--------|
| 内置聊天测试 | Playground 完善 | 无 | **New API** |
| 模型信息展示 | 信息较少 | 非常详细（上下文/功能/代码示例） | **OfoxAI** |
| 登录方式丰富度 | 微信/OIDC/Passkey/2FA | GitHub/邮箱/免密 | **New API** |
| 速率限制可配置 | 完善且暴露 | 未暴露 | **New API** |
| 用量分析维度 | 基础 | 丰富（缓存/搜索/图片/延迟） | **OfoxAI** |
| 团队/工作区 | 个人 | 多团队支持 | **OfoxAI** |
| 生态集成 | 通用 API | 明确兼容大量 AI 编程工具 | **OfoxAI** |
| 扩展功能 | 无 | RAG/MCP/SSO/企业版 | **OfoxAI** |
| 开源可控 | 可自托管二次开发 | 闭源 | **New API** |
| 渠道管理 | 支持多上游渠道配置 | 平台托管 | **New API** |

---

## 结论

**New API** 适合：
- 需要**自托管**、对数据隐私有要求的团队
- 需要**深度定制**（渠道管理、速率限制、登录方式）的场景
- 有技术能力维护开源项目的团队
- 需要**内置 Playground** 快速测试模型的场景

**OfoxAI** 适合：
- 追求**开箱即用**、不想运维基础设施的开发者
- 需要**团队协作**（多团队、Key 归属团队）的场景
- 需要**丰富的模型信息展示**和**详细的用量分析**
- 需要**RAG/MCP/SSO** 等企业级扩展功能
- 使用 **AI 编程工具**（Cursor、Claude Code、Windsurf 等）的开发者
