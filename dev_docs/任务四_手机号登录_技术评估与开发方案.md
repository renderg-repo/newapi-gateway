# 任务四：手机号登录 — Sidecar 可行性评估与最小侵入开发方案

## 一、Sidecar 可行性评估结论

### 1.1 结论：纯 Sidecar 不可行，推荐「混合方案」

手机号登录是**核心认证链路**的扩展，涉及用户模型、登录入口 UI、session 体系三大根基。经代码分析，以下环节**无法通过 Sidecar 隔离**：

| 环节 | 能否 Sidecar | 原因 |
|------|-------------|------|
| User 模型增加 phone 字段 | ❌ 不可 | 登录必须按 phone 查询用户，用户表是唯一数据源 |
| 前端登录/注册页面增加手机号入口 | ❌ 不可 | 必须修改现有 LoginForm.jsx / RegisterForm.jsx 的 UI 结构 |
| 路由注册 | ⚠️ 可部分 | 新接口可放 sidecar，但需在 router/api-router.go 加一行注册调用 |
| SMS 发送服务 | ✅ 可 | 完全独立，可完整 Sidecar 化 |
| 手机号登录/注册接口 | ✅ 可 | 独立 controller，可放 sidecar 包内 |
| 后台 SMS 配置管理 | ✅ 可 | 独立配置项和 UI，可放 sidecar 包内 |
| 验证码存储与校验 | ✅ 可 | 可复用 common/verification.go，或自建 Redis 存储 |

### 1.2 为什么 User 模型无法 Sidecar

现有 `model.User` 结构体是认证的唯一实体：

```go
type User struct {
    Id       int    `json:"id"`
    Username string `json:"username" gorm:"unique;index"`
    Password string `json:"password" gorm:"not null;"`
    Email    string `json:"email" gorm:"index"`
    // ... 其他 OAuth ID 字段
}
```

登录函数 `ValidateAndFill()` 的查询逻辑是：
```go
DB.Where("username = ? OR email = ?", username, username).First(user)
```

如果手机号不加入 User 模型（或扩展表），则：
1. 无法通过 GORM 按手机号查找用户
2. 无法利用现有 `CheckUserExistOrDeleted` 防重复注册
3. 管理后台无法统一查看用户的手机号

**扩展表替代方案？** 建 `user_phones(user_id, phone)` 表虽可避免改 User struct，但：
- 登录需两次查询（先查 phone 得 user_id，再查 User）
- 注册需事务创建 User + Binding，且 User.Username 是必填唯一字段，手机号用户需要生成随机 username（体验差）
- Admin 后台搜索用户手机号需 JOIN

**结论：扩展表方案复杂度高于直接加字段，且侵入点并未显著减少。直接给 User 加 Phone 字段是最务实的选择。**

## 二、最小侵入开发方案

### 2.1 侵入点总览（共 4 处）

| # | 文件 | 改动内容 | 改动量 | Sync 冲突风险 |
|---|------|----------|--------|--------------|
| 1 | `model/user.go` | User struct 加 `Phone` 字段 | 1 行 | 低（字段追加，冲突易解） |
| 2 | `router/api-router.go` | 加一行 sidecar 路由注册 | 1 行 | 极低 |
| 3 | `web/src/components/auth/LoginForm.jsx` | 增加手机号登录 Tab | ~50 行 | 中（UI 代码可能冲突） |
| 4 | `web/src/components/auth/RegisterForm.jsx` | 增加手机号注册选项 | ~60 行 | 中（UI 代码可能冲突） |

其余所有代码（SMS 服务、手机号登录/注册接口、配置管理、后台设置页）全部放入 `sidecar/` 目录，与主代码物理隔离。

### 2.2 数据库层

#### 修改 `model/user.go`

```go
type User struct {
    // ... 原有字段
    Phone  string `json:"phone" gorm:"index" validate:"max=20"`
    // ... 原有字段
}
```

GORM AutoMigrate 会自动为现有表添加 `phone` 列，无需手写 migration。

#### 辅助查询函数（放 `model/user.go`，跟随现有模式）

```go
func IsPhoneAlreadyTaken(phone string) bool {
    return DB.Unscoped().Where("phone = ?", phone).Find(&User{}).RowsAffected == 1
}

func (user *User) FillUserByPhone() error {
    if user.Phone == "" {
        return errors.New("phone is empty")
    }
    return DB.Where("phone = ?", user.Phone).First(user).Error
}
```

**Sync 冲突处理**：如果 upstream 也加了新字段，User struct 的字段追加通常是自动合并的；即使冲突，也是保留两边字段即可，解决成本极低。

### 2.3 后端 Sidecar 包结构

```

├── controller/
│   └── phone_auth.go    # 手机号登录/注册/绑定接口
│   └── sms.go           # 短信验证码发送接口
```

#### `sidecar/router/phone.go`

```go
package router

import (
    "github.com/QuantumNous/new-api/sidecar/controller"
    "github.com/QuantumNous/new-api/middleware"
    "github.com/gin-gonic/gin"
)

func RegisterPhoneAuthRoutes(apiRouter *gin.RouterGroup) {
    // SMS 发送接口（限流）
    apiRouter.POST("/sms/send", middleware.CriticalRateLimit(), controller.SendSMSCode)
    
    // 手机号登录/注册（限流 + Turnstile）
    userRoute := apiRouter.Group("/user")
    {
        userRoute.POST("/login/phone", middleware.CriticalRateLimit(), middleware.TurnstileCheck(), controller.PhoneLogin)
        userRoute.POST("/register/phone", middleware.CriticalRateLimit(), middleware.TurnstileCheck(), controller.PhoneRegister)
        
        // 已登录用户绑定/换绑手机号
        selfRoute := userRoute.Group("/")
        selfRoute.Use(middleware.UserAuth())
        {
            selfRoute.POST("/phone/bind", middleware.CriticalRateLimit(), controller.PhoneBind)
            selfRoute.PUT("/phone/rebind", middleware.CriticalRateLimit(), controller.PhoneRebind)
        }
    }
}
```

#### `sidecar/controller/sms.go`

```go
package controller

import (
    "github.com/QuantumNous/new-api/common"
    "github.com/QuantumNous/new-api/i18n"
    "github.com/QuantumNous/new-api/sidecar/service"
    "github.com/gin-gonic/gin"
)

type SendSMSRequest struct {
    Phone string `json:"phone" binding:"required"`
    Type  string `json:"type" binding:"required,oneof=login register reset_bind"`
}

func SendSMSCode(c *gin.Context) {
    var req SendSMSRequest
    if err := c.ShouldBindJSON(&req); err != nil {
        common.ApiErrorI18n(c, i18n.MsgInvalidParams)
        return
    }
    
    // 限流：同一手机号 60 秒内只能发一次
    if !service.CanSendToPhone(req.Phone) {
        common.ApiErrorI18n(c, i18n.MsgTooManyRequests)
        return
    }
    
    // 生成 6 位数字验证码
    code := common.GenerateVerificationCode(6)
    // 复用现有 verification 机制，key 为手机号，purpose 为 "sms"
    common.RegisterVerificationCodeWithKey(req.Phone, code, common.SMSVerificationPurpose)
    
    // 发送短信
    if err := service.SendSMS(req.Phone, code); err != nil {
        common.SysLog("sms send failed: " + err.Error())
        common.ApiErrorI18n(c, i18n.MsgSMSSendFailed)
        return
    }
    
    common.ApiSuccess(c, nil)
}
```

#### `sidecar/controller/phone_auth.go`

```go
package controller

import (
    "errors"
    "net/http"
    "strings"
    
    "github.com/QuantumNous/new-api/common"
    "github.com/QuantumNous/new-api/controller" // 复用主包的 setupLogin
    "github.com/QuantumNous/new-api/i18n"
    "github.com/QuantumNous/new-api/model"
    "github.com/QuantumNous/new-api/setting"
    "github.com/gin-gonic/gin"
)

type PhoneLoginRequest struct {
    Phone string `json:"phone" binding:"required"`
    Code  string `json:"code" binding:"required"`
}

type PhoneRegisterRequest struct {
    Phone    string `json:"phone" binding:"required"`
    Code     string `json:"code" binding:"required"`
    Password string `json:"password"` // 可选，不填则后续通过忘记密码设置
}

func PhoneLogin(c *gin.Context) {
    var req PhoneLoginRequest
    if err := c.ShouldBindJSON(&req); err != nil {
        common.ApiErrorI18n(c, i18n.MsgInvalidParams)
        return
    }
    
    // 校验验证码
    if !common.VerifyCodeWithKey(req.Phone, req.Code, common.SMSVerificationPurpose) {
        common.ApiErrorI18n(c, i18n.MsgUserVerificationCodeError)
        return
    }
    common.DeleteKey(req.Phone, common.SMSVerificationPurpose)
    
    // 查找用户
    user := model.User{Phone: req.Phone}
    if err := user.FillUserByPhone(); err != nil {
        if errors.Is(err, gorm.ErrRecordNotFound) {
            common.ApiErrorI18n(c, i18n.MsgUserNotExists)
            return
        }
        common.ApiErrorI18n(c, i18n.MsgDatabaseError)
        return
    }
    
    if user.Status != common.UserStatusEnabled {
        common.ApiErrorI18n(c, i18n.MsgUserAccountDisabled)
        return
    }
    
    // 复用主包的 setupLogin 写 session（需确认主包 controller.setupLogin 是否可导出）
    // 如果 setupLogin 是小写，sidecar 包无法调用，需要改为 SetupLogin 或自建 session 逻辑
    controller.SetupLogin(&user, c)
}

func PhoneRegister(c *gin.Context) {
    var req PhoneRegisterRequest
    if err := c.ShouldBindJSON(&req); err != nil {
        common.ApiErrorI18n(c, i18n.MsgInvalidParams)
        return
    }
    
    if !common.RegisterEnabled {
        common.ApiErrorI18n(c, i18n.MsgUserRegisterDisabled)
        return
    }
    
    // 校验验证码
    if !common.VerifyCodeWithKey(req.Phone, req.Code, common.SMSVerificationPurpose) {
        common.ApiErrorI18n(c, i18n.MsgUserVerificationCodeError)
        return
    }
    common.DeleteKey(req.Phone, common.SMSVerificationPurpose)
    
    // 检查手机号是否已注册
    if model.IsPhoneAlreadyTaken(req.Phone) {
        common.ApiErrorI18n(c, i18n.MsgUserExists)
        return
    }
    
    // 生成默认用户名：如 phone_13800138000
    username := "phone_" + req.Phone
    // 如果已存在（极端情况），加随机后缀
    exist, _ := model.CheckUserExistOrDeleted(username, "")
    for exist {
        username = "phone_" + req.Phone + "_" + common.GetRandomString(4)
        exist, _ = model.CheckUserExistOrDeleted(username, "")
    }
    
    password := req.Password
    if password == "" {
        password = common.GenerateRandomKey(16) // 随机密码，用户后续通过其他方式修改
    }
    
    inviterId, _ := model.GetUserIdByAffCode(c.GetString("aff_code"))
    
    user := model.User{
        Username:    username,
        Password:    password,
        DisplayName: username,
        Phone:       req.Phone,
        Role:        common.RoleCommonUser,
        InviterId:   inviterId,
    }
    
    if err := user.Insert(inviterId); err != nil {
        common.ApiError(c, err)
        return
    }
    
    // 自动登录
    controller.SetupLogin(&user, c)
}

func PhoneBind(c *gin.Context) {
    // 已登录用户绑定手机号
    // ... 校验验证码 -> model.DB.Model(&user).Update("phone", req.Phone)
}

func PhoneRebind(c *gin.Context) {
    // 已登录用户换绑手机号（需验证旧手机号或登录状态）
    // ...
}
```

> **注意**：`controller.SetupLogin` 目前是小写 `setupLogin`，sidecar 包无法调用。有两个选择：
> 1. 将主包 `controller/setupLogin` 改为导出 `SetupLogin`（+1 个侵入点）
> 2. 在 sidecar 中复制 setupLogin 的 session 逻辑（零侵入，但少量代码重复）
>
> **推荐方案 2**，因为 session 逻辑只有 10 行左右，复制比导出更干净。

#### `sidecar/service/sms.go`

```go
package service

import (
    "errors"
    "fmt"
    "sync"
    "time"
    
    "github.com/QuantumNous/new-api/common"
)

type SMSProvider interface {
    Send(phone string, code string) error
}

var (
    sendRecord sync.Map // phone -> lastSendTime
    provider   SMSProvider
)

func init() {
    // 根据配置初始化 provider
    switch common.OptionMap["SmsProvider"] {
    case "aliyun":
        provider = &AliyunSMSProvider{}
    case "tencent":
        provider = &TencentSMSProvider{}
    case "twilio":
        provider = &TwilioProvider{}
    default:
        provider = nil
    }
}

func CanSendToPhone(phone string) bool {
    if last, ok := sendRecord.Load(phone); ok {
        if time.Since(last.(time.Time)) < 60*time.Second {
            return false
        }
    }
    return true
}

func SendSMS(phone string, code string) error {
    if provider == nil {
        return errors.New("sms provider not configured")
    }
    if err := provider.Send(phone, code); err != nil {
        return err
    }
    sendRecord.Store(phone, time.Now())
    return nil
}

    return nil
}

func (t *TencentSMSProvider) Send(phone string, code string) error {
```

## 五、关键决策点

### 决策 1：User 模型加字段 vs 扩展表

- **加字段**：推荐。侵入点只有一个文件的一行代码，sync 冲突易解。
- **扩展表**：不推荐。虽然避免了改 User struct，但引入两次查询、随机 username 生成、事务复杂度，整体成本更高。

### 决策 2：setupLogin 复用 vs 复制

- **复用（导出 SetupLogin）**：+1 个侵入点（改 controller/user.go 的小写函数为大写），但零代码重复。
- **复制 session 逻辑**：零侵入，sidecar 包内自包含 session 写入代码（约 15 行）。

**推荐复制**，因为 session 逻辑稳定且简短，复制比跨包依赖更利于隔离。

### 决策 3：配置初始化放主包 option.go vs sidecar 自管理

- **放 option.go**：跟随现有模式，统一但 +1 侵入点。
- **sidecar 自管理**：零侵入，首次读取时 lazy init。

**推荐 sidecar 自管理**。
