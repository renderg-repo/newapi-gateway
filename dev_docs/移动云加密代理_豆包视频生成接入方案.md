# 移动云加密代理·豆包视频生成接入方案

> 目标：移动云渠道的豆包（Doubao/Seedance）视频生成，所有任务须经过部署的加密代理才能访问。本方案梳理从前到后的完整流程，并给出最小侵入的代码改动。

## 一、背景与现状

### 1.1 火山引擎直连现状（当前代码）

```
创建任务         轮询(每15s)                    前端预览
POST {base}/api/v3/contents/generations/tasks
                → FetchTask GET .../tasks/{id}
                → ParseTaskResult 取 content.video_url
                → task.PrivateData.ResultURL = video_url(TOS预签名URL)
                                                   → 前端开弹窗，直接用该URL作为 <video> src
```

前端预览链路：`web/classic/src/components/table/task-logs/TaskLogsColumnDefs.jsx:410-432`，点击后 `openVideoModal(record.result_url)` 直接播放。

### 1.2 移动云加密代理引入的问题

移动云代理返回的 `video_url` 是**加密的 TOS 地址**，浏览器无法直接播放。必须调用代理的 `/download` 接口做 RSA 解密后才能拿到明文 MP4。

### 1.3 现有可复用机制

代码库已具备通用视频代理入口 `VideoProxy`（`/v1/videos/:task_id/content`），全程流式转发视频。移动云只是「某个渠道需要走 download 解密」，改动可完全收敛到该入口。

## 二、确认的关键决策

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 移动云渠道如何识别 | **通过 BaseURL 区分**：baseURL 含 `/aicc/` 前缀即移动云；火山直连无此前缀 |
| 2 | encrypted_key 来源 | **忽略**。代理 `/download` 端点内部自动完成 RSA 解密，无需我们传该字段 |
| 3 | 请求/响应字段 | **与火山引擎一致**（duration 秒、ratio、model 等） |
| 4 | download 鉴权 | `Authorization: Bearer <apiKey>` |
| 5 | 创建请求字段 | **与火山引擎一致**，复用现有 `requestPayload` |

## 三、整体架构（目标态）

```
创建任务（走移动云代理）        轮询                         前端预览
POST aicc/seedance/api/v3/contents/generations/tasks
                              FetchTask GET .../tasks/{id}
                              → video_url 是加密地址，丢弃
                              → ResultURL = BuildProxyURL(taskID)  ← 关键变化
                                                                    ↓
前端点「点击预览视频」 → 请求 /v1/videos/{taskID}/content
                                ↓
                        VideoProxy 查渠道 → ChannelTypeDoubaoVideo
                                ↓
                        调用代理 GET {base}/aicc/seedance/api/v3/.../{上游taskId}/download?model=xxx
                        带 Authorization 头
                                ↓
                        拿到解密后的明文 MP4 → 流式转发给 <video>
```

## 四、改动清单（从前到后）

### 改动 1：`relay/channel/task/doubao/adaptor.go`

**1a. 新增 helper**（文件末尾）：

```go
// isMobileCloud 判断当前渠道是否为移动云加密代理（baseURL 带 /aicc/ 前缀）
func (a *TaskAdaptor) isMobileCloud() bool {
    return strings.Contains(a.baseURL, "/aicc/")
}
```

**1b. 改动 `ParseTaskResult`**（`adaptor.go:335-338`）——移动云成功时置 `Url=""`：

```go
case "succeeded":
    taskResult.Status = model.TaskStatusSuccess
    taskResult.Progress = "100%"
    if !a.isMobileCloud() {
        // 直连火山：直接保存 TOS 预签名 URL
        taskResult.Url = resTask.Content.VideoURL
    }
    // 移动云：Url 留空 → 轮询回退到 BuildProxyURL
    // 解析 usage 信息用于按倍率计费
    taskResult.CompletionTokens = resTask.Usage.CompletionTokens
    taskResult.TotalTokens = resTask.Usage.TotalTokens
```

> `BuildRequestURL`、`FetchTask`、`BuildRequestHeader` **无需改动**：baseURL 已含 `/aicc/seedance`，拼接路径 `api/v3/...` 一致；auth 走 `Bearer` 一致；字段与火山一致。

### 改动 2：`controller/video_proxy.go`

**2a. 新增 helper**（同文件或新建 `controller/video_proxy_mobilecloud.go`）：

```go
func isMobileCloudBaseURL(baseURL string) bool {
    return strings.Contains(baseURL, "/aicc/")
}
```

**2b. 改动 `switch channel.Type`**（`:87`）新增 `ChannelTypeDoubaoVideo` 分支：

```go
case constant.ChannelTypeDoubaoVideo:
    if isMobileCloudBaseURL(baseURL) {
        // 移动云：经代理 /download 解密后转发明文 MP4
        videoURL = fmt.Sprintf("%s/api/v3/contents/generations/tasks/%s/download?model=%s",
            baseURL,
            task.GetUpstreamTaskID(),
            url.QueryEscape(task.Properties.OriginModelName),
        )
        req.Header.Set("Authorization", "Bearer "+channel.Key)
    } else {
        // 直连火山：保持原逻辑，直接转发 GetResultURL
        videoURL = task.GetResultURL()
    }
```

> 注意：`video_proxy.go` 已 import `net/url` 与 `fmt`、`strings`，无需新增 import。
> 构造出的 `videoURL` 会继续走后续统一逻辑：SSRF 校验 → `req.URL` 解析 → `client.Do` → 流式转发。

## 六、完整数据流

```
创建任务
  POST {base}/aicc/seedance/api/v3/contents/generations/tasks
  → 返回 task_id

轮询（每 15s，service/task_polling.go）
  FetchTask GET {base}/aicc/seedance/api/v3/.../tasks/{id}
  → 返回 status=succeeded, content.video_url=加密地址
  → ParseTaskResult: 移动云 → Url="" → ResultURL=BuildProxyURL(taskID)
  → 存入 DB

前端预览
  用户点击「点击预览视频」
  → 请求 /v1/videos/{taskID}/content
  → VideoProxy 查出 task，查渠道 = ChannelTypeDoubaoVideo
  → 判断 baseURL 含 /aicc/ → 移动云分支
  → 构造 GET {base}/aicc/seedance/api/v3/.../tasks/{上游taskId}/download?model=xxx
  → 带 Bearer auth 请求移动云代理
  → 代理 RSA 解密 → 返回明文 MP4 流
  → 直接转发给前端 <video> 播放
```

## 八、风险与注意事项

1. **移动云 baseURL 配置**：控制台新建移动云渠道时，Base URL 必须填含 `/aicc/seedance` 前缀的地址（如 `http://localhost:8080/aicc/seedance`），否则无法命中 `isMobileCloud` 判断。
2. **上游 task id 一致性**：`BuildRequestURL` 返回的 `PublicTaskID` 与 `FetchTask`/`download` 用的 `GetUpstreamTaskID()` 需一致，确保 download 能定位到正确任务。
3. **download 超时**：`VideoProxy` 已设 60s 转发超时，视频较大时注意；可评估是否需针对视频放大。
4. **SSRF 校验**：移动云 download URL 会经过 `ValidateURLWithFetchSetting`，需确保移动云域名不在黑名单/在内网放行范围内（`AllowPrivateIp`）。
