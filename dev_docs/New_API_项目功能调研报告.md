# New API 项目功能调研报告

## 一、Chat 聊天功能

### 现状

| 功能 | 支持情况 | 说明 | 解决方案 |
|------|----------|------|----------|
| 文本对话 | 已支持 | Playground 内置完整聊天测试功能 | |
| 图片输入(Vision) | 已支持 | Playground 支持粘贴/输入图片URL进行多模态对话 | |
| 流式输出 | 已支持 | 可调节开关 | |
| 自定义请求体 | 已支持 | 支持直接编辑 JSON 请求体发送任意请求 | |
| 文生图 | 间接支持 | 后端 relay 支持 images/generations 端点，但 Playground 没有专门的文生图测试 UI | 类似并行智算的实现方式：体验中心：增加适配页面，api key部分使用下拉列表让用户选择自己的key，有额度则可以测试调用。模型服务接口直接调用NewApi提供的接口。 |
| 文生视频 | 间接支持 | 后端支持 video 相关 task 端点（如 sora、kling、vidu 等），但 Playground 没有专门的测试 UI | 同上 |
| 文本转语音(TTS) | 间接支持 | 后端 relay 支持 audio/speech 端点，但 Playground 没有专门的 TTS 测试 UI | 同上 |

### 实现评估

如需实现专门的文生图、文生视频、TTS 测试界面：
- 可行性：可行
- 难度：中等
- 实现条件：
  1. 扩展 Playground 设置面板，增加端点类型选择（chat/completions、images/generations、audio/speech 等）
  1. 根据端点类型动态切换输入表单（如文生图需要 prompt/size/quality，TTS 需要 text/voice/speed）
  1. 后端 relay 已完整支持这些端点，无需改动

## 五、请求速率限制

### 现状

| 功能 | 支持情况 | 说明 |
|------|----------|------|
| 模型请求限流 | 已支持 | 按用户限制，支持周期（分钟）、总请求次数、成功请求次数 |
| 分组差异化限流 | 已支持 | 支持 JSON 配置不同用户组的限流策略 |
| Redis 存储 | 已支持 | 高并发场景下推荐使用 |
| 内存存储 | 已支持 | 无 Redis 时的降级方案 |
| 全局 Web 限流 | 已支持 | 按 IP 限流 |
| 全局 API 限流 | 已支持 | 按 IP 限流 |
| 搜索限流 | 已支持 | 按用户 ID 限流（防代理轮换） |

### 配置示例

模型请求速率限制后台配置项：
- ModelRequestRateLimitEnabled：是否启用
- ModelRequestRateLimitDurationMinutes：限制周期（分钟）
- ModelRequestRateLimitCount：每周期最多请求次数（含失败）
- ModelRequestRateLimitSuccessCount：每周期最多成功请求次数
- ModelRequestRateLimitGroup：分组差异化配置，如 {default: [200, 100], vip: [0, 1000]}

### 结论

完全满足需求，速率限制系统非常完善，支持多维度和分组策略。

## 六、Uptime 监控

### 现状

| 功能 | 支持情况 | 说明 |
|------|----------|------|
| 外部 Uptime Kuma 集成 | 已支持 | 支持配置多个 Uptime Kuma 实例的分组，在首页展示监控状态面板 |
| Channel 自动测试 | 已支持 | 可配置定时自动测试各渠道连通性，失败自动禁用，成功自动启用 |
| 系统资源监控 | 已支持 | CPU、内存、磁盘、GC 等性能指标（Root 权限查看） |

### 配置详情

- 后台配置项 ：是否启用面板（默认 true）
- ：JSON 数组配置，每组需填写 url、slug、categoryName
- 最多支持 20 个分组
- 对外暴露 接口（无需认证）

### 结论

支持外部 Uptime Kuma 集成和内部渠道自动测试，但**无内置主动探测机制**（依赖外部工具）。

## 七、IP 黑名单

### 现状

| 功能 | 支持情况 | 说明 |
|------|----------|------|
| Token 级别 IP 白名单 | 已支持 | 每个 API Key 可配置允许访问的 IP/CIDR 列表，不在列表中的请求返回 403 |
| 出站请求 IP/域名过滤（SSRF 防护） | 已支持 | 支持黑白名单模式，可限制私有 IP、端口、域名解析后的 IP |
| 全局入站 IP 黑名单 | 不支持 | 没有针对所有入站请求的全局 IP 拦截中间件 |

### 实现评估

如需实现全局 IP 黑名单：
- 可行性：可行
- 难度：低
- 实现条件：
  1. 新增全局配置项（如 ）
  1. 在 middleware 层增加 IP 检查逻辑（可复用现有 ）
  1. 对命中黑名单的 IP 返回 403 并记录日志

### 结论

IP 过滤能力主要集中在 **Token 级别**和**出站 SSRF 防护**，缺少**全局入站黑名单**功能。
